### 세부 구현 항목
1. **캐릭터, 몬스터 스탯**
    - 캐릭터와 몬스터가 공통으로 사용하는 스탯 컴포넌트를 구현하여 체력, 공격력 등 데이터 관리.
    스탯 로직을 Actor Component로 분리하여 여러 액터에서 재사용할 수 있도록 함.
2. **리슨서버를 활용한 멀티플레이**
    - 장착 장비 정보를 Replication으로 동기화하고, RepNotify를 활용하여 장비 배열이 변경될 때마다 클라이언트에서 메쉬를 갱신하도록 구현.
    Culling Distance로 인해 액터가 다시 생성되어도 장착 상태가 복원되도록 하기 위함.
    - 스탯 컴포넌트에서 체력 소진을 감지하면 서버가 플레이어의 사망 상태를 갱신하고 이동을 제한하도록 구현. 이후 체력 값이 복제될 때 RepNotify를 통해 각 클라이언트에서 사망 애니메이션 및 후처리를 실행.
    Multicast RPC로 사망 연출을 호출하면 복제된 체력과 사망 처리 타이밍이 어긋날 수 있기에 이런 오류를 해결하기 위함.
3. **UI와 캐릭터 데이터 연동**
    - UI의 상호작용은 Player Controller를 통해 Server RPC를 호출하고 캐릭터 로직을 수행.
    클라이언트가 데이터를 직접 변경하지 않도록 분리하기 위함.
4. **아이템 착용/ 해제**
    - 아이템 장착 시 게임모드에서 특정 아이템의 정보를 가져와 Player State에 저장 후 장착한 아이템 정보를 바탕으로 가감된 스탯을 적용.
    Player State를 이용하여 리스폰 이후에도 사망 전 장착한 장비를 복원할 수 있도록 함.
5. **스킬 착용/ 해제, 사용**
    - Primary Data Asset을 기반으로 부모 스킬 에셋을 정의 후, 이를 상속하여 개별 스킬 구조를 제작.
    스킬을 데이터 중심으로 관리하여 불필요한 액터 생성 비용을 줄이고, 새로운 스킬 추가 시 데이터 에셋만 제작하면 됨.
